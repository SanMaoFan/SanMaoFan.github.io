简介

视图过渡 API（View Transition API）提供了一种轻松地创建不同网站视图之间的动画过渡的机制。这包括在单页应用（SPA）中的 DOM 状态之间设置动画，以及在多页应用（MPA）中的文档之间的导航设置动画。MDN 中将其概念介绍为：视图过渡是一种流行的设计选择，可以减少用户认知负荷，帮助他们保持上下文，并减少他们在应用程序的状态或视图之间移动时感知的加载延迟。以小红书的功能来举例，在以下视频中，在进入一篇博文时，点击博文中的图片，其图片会从原本的屏幕顶部，移动到屏幕中部，并且背景逐渐变黑。

此 API 工作原理为：先给最开始的页面(旧页面)拍快照，当视图变动后(既可以是当前页面 SPA 过渡，也可以是跨页面 MPA 过渡)，API 将新视图中的快照捕获为实时表示的形式，接着在两张页面快照之间做动画，旧页面快照以“淡出”动画形式显示，而新视图快照以“淡入”形式呈现动画效果。具体请参考官方文档:MDN 视图过渡过程

但以上效果仅仅是将图片变大后直接弹窗淡出展示，如果想要从缩略图大小平滑变大成弹窗图片大小并展示，这该怎么做呢？

这里需要引入 view-transition-name 属性，它是为 CSS 属性选中的元素提供了一个独特的标识名称，并使其参与与根视图过渡分开的视图过渡，如果指定了 none 值，则不参与任何视图过渡。也就是告诉浏览器，旧页面的缩略图和新页面的弹窗大图是同一个东西，而将这两个元素使用 view-transition-name 设置同一个名字，也就让浏览器将它们联系了起来。有名字的缩略图，浏览器会将其分离出来并单独给缩略图拍一张快照，然后从缩略图位置大小慢慢变成大图的位置和大小。

接下来便可以看到缩略图平滑变大并达到弹窗图片的位置，这里需要额外注意的是，thumbnail.style.viewTransitionName = 'active-image' 代码是当缩略图被点击时，才给名称，而不能一开始就给所有缩略图加上同一个名称，否则动画会失效，这是因为全部缩略图都是同一个名称，导致浏览器不知道是哪一张需要被快照，从而导致整个 transition 被跳过，直接修改 DOM；还有导致动画失效的另一个问题，是当弹窗大图淡出时，其缩略图的 viewTransitionName 名称没有移除而导致的，这是因为同一时间，一个名字只能给一个元素使用，所以需要在启动视图过渡时，其函数内部需要设置 thumbnail.style.viewTransitionName = '' 来让缩略图的名称移除。

至此，类小红书图片的过渡效果便完成，但如果需要在弹窗被关闭时，也将大图回到一开始的缩略图位置，需要怎么做呢？

实际上思路和刚刚缩略图以及弹窗大图转换 viewTransitionName 的思路一样，在关闭弹窗时，将弹窗的 viewTransitionName 设置为空，而对应缩略图设置为刚刚弹窗大图的 viewTransitionName 名称即可。

这样便可以在弹窗关闭时，其大图重新回到缩略图位置，但是第一张图打开是正常的，而打开第二张图时，动画效果又消失了，这是因为其缩略图的名称未置空造成了，如果想在动画完成后，将所有变量初始化，这里推荐使用 API 中的 finished 属性 ，这是一个 Promise 方法，所以可以使用 async await 或者调用 finally 函数来完成接下来的任务，在上面代码中，已经使用 transition 变量来存储 API 内容了，所以使用 finished 属性只需要这样调用：
